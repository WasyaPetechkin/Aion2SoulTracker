# Collection integrity — 0.3.7

## Русский

Изменения закрывают программную часть критических рекомендаций C1–C3 из аудита: принадлежность коллекции сессии, единый учёт потерь и воспроизводимые проверки точности. Новые зависимости не добавлены. Приложение по-прежнему пассивно читает трафик; игровые запросы, инъекции и изменение маршрутов не используются.

### C1. Кому принадлежит коллекция

`GameProcessLocator.FindConnections` передаёт PID владельца TCP-соединения. `PacketPipeline` создаёт `StreamContext` с адресами соединения, PID, временем первого наблюдения и монотонным поколением. Новый SYN с другой начальной последовательностью и смена PID создают новое поколение. Повтор того же SYN не создаёт новую сессию.

`CollectionSession` принимает события только для выбранного процесса. Новый поток должен предоставить имя персонажа/сервер из существующего парсера и полный снимок коллекции. Оба порядка поддержаны: идентификация перед снимком и снимок перед идентификацией. Во втором случае начисления после снимка временно сохраняются и применяются после подтверждения. Снимок из другой сессии не получает имя ранее выбранного персонажа автоматически.

После принятого перехода прежний активный поток исключается. Ранее открытое, но ещё не использовавшееся соединение может стать активным после свежего снимка и идентификации. Смена персонажа на том же TCP-потоке очищает старую коллекцию; прежняя эвристика близости по времени в 30 секунд удалена. Завершение процесса освобождает владельца, но не позволяет его старым событиям снова стать актуальными.

Полный снимок заменяет коллекцию целиком, включая пустые коллекции и счётчики ещё не открытых питомцев. Снимок старше последнего применённого начисления отклоняется. Повторяющиеся одинаковые начисления сами по себе не считаются дубликатами: игрок действительно может получить две одинаковые души. Повторы удаляются на уровне последовательности TCP.

### C2. Что считается потерей

`LossEvidence` содержит соединение, причину, время, PID и границы последовательности, когда они известны. Потеря относится к конкретному `StreamContext`.

| Участок | Поведение |
| --- | --- |
| `GameConnectionGate` | Ограниченный буфер до подтверждения PID: 4096 сегментов / 2 МиБ / 10 секунд. После удаления сегмента остаются метаданные потери, максимум для 512 соединений. Чужой трафик не сбрасывает коллекцию. |
| `PacketPipeline` до распознавания игры | Переполнение буфера 512 КиБ и пропуски обнаружения запоминаются; потеря передаётся только после распознавания игрового потока. |
| `TcpReassembler` | Повторы и пересечения обрезаются; переставленные сегменты ждут восстановления. Пропуск объявляется после 5 секунд при поступлении следующих данных либо переполнении буфера 2 МиБ. |
| Известный диапазон потери активного потока | Уже доставленный диапазон игнорируется. Иначе даётся время на повторную доставку; журнал ограничен 64 диапазонами на поток. |
| `FrameDecoder` | Ошибки кадрирования и сжатия передаются владельцу потока. Размер результата LZ4 должен точно совпасть с объявленным. |
| Обработчики | Исключение при обработке игрового сегмента делает этот поток недостоверным. Ошибка записи необязательного PCAP отдельно учитывается и не блокирует разбор полученного пакета. |

Тишина в сети, общий статус ошибки адаптера без свидетельства потери и шум другого соединения сами по себе не сбрасывают коллекцию. Фатальный сбой, закрывающий весь захват, сбрасывает доверие ко всем его игровым потокам. Суммарный счётчик Npcap `Dropped` не позволяет определить конкретного персонажа и не используется как самостоятельное доказательство потери его душ.

После подтверждённой потери новые начисления не применяются, пока не получены новый снимок и идентификация. Недостающие души не вычисляются по догадке. Накопленные значения остаются доступны как устаревшие данные. Некорректная сумма начислений проверяется до изменения коллекции; отказ применения не оставляет живую сессию доверенной.

### Ограничения и проверка в игре

- Привязка использует PID и поколение TCP, а не время создания процесса Windows. Ненаблюдавшийся перезапуск с совпадением PID, адресов и последовательности нельзя надёжно распознать по этим данным.
- Имя и сервер берутся из существующего парсера. Неизвестный сервер обозначается нулём; это не глобальный идентификатор персонажа. Получение устойчивого серверного ID персонажа остаётся отдельной задачей.
- Начисление на новом потоке без полного снимка не доказывает непрерывность, даже если имя совпадает. Может понадобиться повторный вход. Уже использованный и затем закрытый для коллекции поток не активируется вновь без нового транспортного поколения.
- После потери последнего пакета и полного прекращения трафика нет данных для немедленного обнаружения TCP-дыры; интерфейс показывает ожидание сети. При поступлении новых данных работает обычное восстановление TCP.
- Буферы и журналы ограничены. Очень старые поколения за пределами истории не могут получить доверие только из сохранившегося имени; нужен новый обмен.
- Локальные тесты и воспроизведение записей не заменяют длительную игру. Для этой версии отдельно нужны вход, начисления, переход в данж и обратно, смена персонажа, переключение VPN и LagoFast. Отсутствие повторных релогов во всех таких сценариях пока не подтверждено.

## English

This change implements the software portion of audit priorities C1–C3. `CollectionSession` binds progress to a process, transport generation and parsed character identity. A new stream requires both a full collection and identity, in either order. Retired streams cannot mutate the selected collection; an unused pre-opened connection can take over after fresh confirmation. Repeated identical gain messages are valid separate events; TCP retransmissions are removed by sequence, not by their contents.

`LossEvidence` carries flow-specific buffer, TCP, decoder and handler failures. Ownership evidence and pending data are bounded. Missing ranges already delivered are ignored; unresolved ranges get time for retransmission. Silence and unrelated traffic are not treated as collection loss. Unrecoverable loss requires fresh synchronization; missing gains are never invented. LZ4 output length must match its declared size, and invalid aggregate gains cannot partially change counters while remaining trusted.

Tests cover session transitions, ownership, malformed input and 180 randomized transport arrangements against an independent progress oracle. Four private capture replays matched direct snapshot/gain application; one correctly remained untrusted after two actual TCP gaps. No private captures or new dependencies are distributed.

Limits: PID is not a process creation identity; character names/servers depend on the existing parser; a new flow without a full snapshot cannot inherit trust. Data silence cannot prove whether an unseen final packet was lost. Extended live VPN/LagoFast, dungeon-transfer and character-switch testing remains necessary. Run the core tests and the EXE verification command shown above; the latter is synthetic and does not start capture.
