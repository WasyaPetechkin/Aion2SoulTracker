# Code signing policy

Версия 0.2.0 пока распространяется как **неподписанная тестовая сборка**.
Наличие исходного кода и SHA256 не заменяет подпись доверенного издателя.

## Что требуется от владельца проекта

Для распространения EXE нужен сертификат Code Signing, выданный доверенным
центром сертификации, либо одобренная служба подписи открытых проектов.
Владелец проходит проверку личности непосредственно у поставщика.
Не отправляйте документы, пароль, PIN, закрытый ключ или платёжные данные в GitHub.

Проверено 19 октября 2026 года:

- [Microsoft Artifact Signing](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)
  доступен физлицам только из США и Канады; для физлица из Украины этот маршрут пока не подходит.
- [Certum Open Source](https://shop.certum.eu/open-source-code-signing-on-simplysign.html)
  предлагает сертификат физического лица для открытого ПО, но страница сейчас отмечена
  «out of stock». Доступность для Украины и итоговую стоимость нужно подтвердить у поставщика до оплаты.
- [SSL.com Code Signing](https://www.ssl.com/products/software-integrity/code-signing/)
  предлагает Individual Validation. Требуется подтвердить возможность выдачи для Украины,
  цену сертификата и отдельную стоимость облачной подписи/токена.
- [SignPath Foundation](https://signpath.org/terms) рассматривает открытые проекты бесплатно,
  но требует опубликованный проект с подтверждаемой репутацией и одобряет заявки индивидуально.
  Проект пока не принят в эту программу. Материалы и сторонние компоненты также требуют проверки условий.

Подпись сообщает Windows имя издателя и защищает целостность файла.
Она не гарантирует немедленное отсутствие SmartScreen у новой версии.
[Объяснение Microsoft](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).

## Сборка после выпуска сертификата

Установите клиент вашего токена/облачного провайдера и Windows SDK SignTool.
Сертификат должен быть доступен в личном хранилище текущего пользователя Windows.
Задайте в локальном PowerShell:

```powershell
$env:AION_SIGN_CERT_SHA1 = '<40-символьный отпечаток выданного сертификата>'
$env:AION_SIGNTOOL = '<полный путь к signtool.exe>'
$env:AION_TIMESTAMP_URL = '<RFC3161 URL от поставщика сертификата>'
./build.ps1 -SigningScript ./scripts/sign-file.ps1
```

Скрипт подписывает собственные EXE/DLL, затем Inno Setup подписывает установщик
и деинсталлятор. Подпись и временная метка проверяются; ошибка останавливает сборку.
Исходный архив и контрольные суммы входят в поставку. Сторонние библиотеки не
переподписываются от имени проекта. Путь подписи пока не проверен с реальным сертификатом.
Без `-SigningScript` создаётся явно неподписанная сборка для тестирования.

Закрытые ключи остаются в токене/облаке поставщика. Для другой службы подписи можно
передать совместимый PowerShell-адаптер с параметром `-FilePath`; он должен подписать
файл на месте, добавить временную метку и завершиться ошибкой при неудаче.
